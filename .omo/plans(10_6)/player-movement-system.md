# Player Movement System Plan (v2 - Run & Gun)

Unity 2D 횡스크롤 총게임의 플레이어 이동 시스템을 구현해줘.

먼저 현재 프로젝트의 Player 오브젝트, Rigidbody2D, Collider2D, 기존 PlayerController 및 이동 관련 스크립트를 확인한 뒤 구현한다. 기존 구조와 충돌하지 않도록 필요한 부분만 수정한다. Unity 버전에 따라 Rigidbody2D 속도 API(velocity / linearVelocity)가 다르므로 프로젝트가 쓰는 쪽에 맞춘다.

상태 우선순위와 상태별 이동 허용 규칙은 player-state-input-system.md를 따른다.

==================================================
[1. 기본 이동 (가속 / 감속 / 급정거)]
==================================================

플레이어는 좌우 방향으로 이동하며, 다음 느낌을 목표로 한다.

- 방향키를 누르고 있으면 최대 이동 속도까지 일정하게 가속한다.
- 방향키를 떼면 감속하며 멈춘다. (즉시 멈추지 않고 미끄러지는 구간이 있다.)
- 이동 중 반대 방향키를 누르면 급정거한다. 감속 구간 없이 즉시(또는 매우 빠르게) 속도를 0으로 만든 뒤 반대 방향으로 다시 가속한다.

구현 규칙:

- 입력 방향과 현재 속도 방향이 같으면 가속 값을 쓴다.
- 입력이 없으면 감속 값을 쓴다.
- 입력 방향과 현재 속도 방향이 반대이면 "반전 감속(Turn Deceleration)" 값을 쓴다. 이 값이 매우 크면 급정거처럼 동작하고, 무한대(또는 즉시 0 처리) 옵션도 둔다.
- 급정거 후 남은 프레임에서 반대 방향 가속이 이어지도록 해서 입력이 한 프레임 씹히는 느낌이 없게 한다.
- 속도를 직접 덮어쓰는 방식과 물리 힘 방식 중 프로젝트의 기존 구조에 맞는 쪽을 쓰되, 최대 속도를 넘지 않게 한다.

조절 가능한 값(Inspector):

- 최대 이동 속도
- 가속도
- 감속도 (입력 없음)
- 반전 감속도 (반대 입력, 급정거 정도)
- 방향 전환 시 즉시 정지 옵션

==================================================
[2. 이동하면서 사격]
==================================================

총게임이므로 이동과 사격이 서로 막지 않는 것이 기본이다.

- 사격 중에도 이동 가능 (기본값)
- 사격 중 이동 속도 배율을 Inspector에서 조절할 수 있게 한다. (1.0이면 감속 없음)
- 사격 중 제자리 고정 옵션(조준 고정)을 둘 수 있게 한다.
- 이동 방향과 바라보는 방향이 다를 수 있다. (뒤로 걸으며 사격) 이 경우 이동은 입력 방향, 바라보는 방향은 조준 방향을 따른다.
- 사격 반동(Recoil)으로 인한 뒤로 밀림은 옵션으로 두고, 기본은 꺼 둔다.

==================================================
[3. 지상과 공중 이동]
==================================================

지상 이동과 공중 이동을 구분한다.

- 지상에서는 [1]의 가속 / 감속 / 반전 감속 값을 사용한다.
- 공중에서도 방향을 어느 정도 바꿀 수 있어야 한다.
- 공중은 지상과 별도의 값을 사용한다. (공중 가속도, 공중 감속도, 공중 반전 감속도)
- 공중에서 반대 방향 입력 시 지상처럼 급정거할지, 부드럽게 방향을 바꿀지는 공중 반전 감속도 값으로 조절한다. (기본값: 지상보다 약하게)
- 공중에서 방향을 바꿀 때 기존 속도와 새 입력이 비정상적으로 충돌하지 않도록 한다.
- 공중에서도 사격이 가능하다. 공중 사격 중 이동 규칙은 지상과 별도로 설정할 수 있다.

==================================================
[4. 점프 (가변 점프)]
==================================================

점프는 Rigidbody2D의 물리 구조와 충돌하지 않도록 구현한다.
점프 키를 누르는 시간에 따라 점프 높이가 달라지는 가변 점프를 기본으로 한다.

- 살짝 누르면 낮게 뛴다. (최소 점프 높이를 보장한다.)
- 길게 누르면 가장 높이, 가장 오래 뜬다. (최대 점프 높이)
- 점프 키를 떼면 상승 중일 때 하강 속도를 더 크게 준다. (중력 배율을 높이거나 상승 속도를 깎는 방식)
- 키를 계속 누르고 있어도 최대 높이에 도달하면 자연스럽게 하강한다.
- 하강 중에는 상승 중보다 큰 중력 배율을 적용할 수 있게 한다. (Fall Gravity Multiplier)
- 점프 도중 좌우 방향 전환이 가능하다. ([3] 공중 이동 규칙 사용)

조절 가능한 값(Inspector):

- 점프 힘
- 최소 점프 유지 시간 또는 최소 높이
- 최대 점프 높이
- 점프 키를 뗐을 때 하강 배율 (Jump Cut Multiplier)
- 하강 중력 배율
- 최대 낙하 속도

점프 컷 방식은 활성/비활성 옵션으로 둔다. (끄면 고정 높이 점프)

Coyote Time과 Jump Buffer를 Inspector에서 활성화/비활성화할 수 있도록 한다.
Jump Buffer 입력은 입력 시스템의 버퍼를 사용한다.

==================================================
[5. 바닥 판정]
==================================================

단순히 플레이어의 Y좌표를 기준으로 바닥을 판단하지 않는다.

Collider2D 또는 Ground Check를 이용해 실제 지면 접촉을 판단한다.

- 내부 플랫폼도 실제 플레이어 이동용 Ground라면 정상적으로 바닥으로 인식한다.
- 일방향 플랫폼, 경사면, 이동 플랫폼이 프로젝트에 있는지 확인하고, 있으면 처리한다. 없으면 확장 가능하게만 둔다.
- 벽에 붙어 떨어지지 않는 문제를 막기 위해 마찰이 없는 Physics Material 사용을 확인한다.
- 카메라용 Room Boundary와 플레이어 이동용 Ground는 서로 다른 역할이므로 혼동하지 않는다.

==================================================
[6. 상태별 이동 제한]
==================================================

피격, 대시, 사망 등의 상태에서 이동 가능 여부는 State System의 상태별 허용 표에서 가져온다.

각 상태마다 이동을 하드코딩으로 막지 않는다.

==================================================
[7. 대시 및 넉백 (외부 속도)]
==================================================

대시가 포함되어 있다면 일반 이동 속도와 분리한다.
대시와 마찬가지로 피격 넉백도 "외부 속도"로 취급한다.

- 대시나 넉백 중에는 일반 이동 입력이 해당 속도를 덮어쓰지 않는다.
- 종료 후 정상적인 이동 상태로 자연스럽게 복귀한다.
- 넉백 값은 Health/Damage 시스템에서 전달받는다.

==================================================
[8. 물리 및 애니메이션 연결]
==================================================

Rigidbody2D의 실제 속도와 애니메이션 상태가 일치하도록 한다.

- 수평 속도 > 일정 값 → Run
- 수직 속도 > 0 → Jump/Rising
- 수직 속도 < 0 → Fall
- 지상 + 이동 없음 → Idle

애니메이션 전환 로직과 실제 이동 로직을 서로 강하게 결합하지 않는다.
애니메이션은 이동 결과값을 읽기만 한다.

==================================================
[9. 관용 시스템 (플레이어 실수 보정)]
==================================================

조작이 너그럽게 느껴지도록 플레이어의 작은 실수를 보정한다.
각 보정은 Inspector에서 개별로 켜고 끌 수 있고 값을 조절할 수 있게 한다. (코요테 타임과 점프 버퍼는 [4] 참고)

(1) 코너 보정 (Corner Correction)

- 상승 중 머리가 천장 모서리에 걸릴 것 같으면 옆으로 밀어서 통과시킨다.
- 상승 속도가 양수일 때만 작동한다.
- 머리 좌/우 위쪽에 짧은 Raycast/BoxCast를 쏴서 한쪽만 막혔는지 확인하고, 막히지 않은 쪽으로 수평 이동한다. 이때 수직 속도는 유지한다.
- 보정 거리 한도(픽셀 또는 유닛)를 Inspector에서 조절한다. 한도를 넘으면 평소처럼 천장에 부딪힌다.
- 보정 방향에 빈 공간이 있는지 먼저 확인해서 벽 쪽으로 끌려가는 이상한 이동을 막는다.
- 보정은 입력과 싸우지 않도록 한 번만 밀어 준다.
- 충돌 처리로 상승 속도가 0이 되기 전에 판정해야 한다. 판정 시점에 주의한다.

(2) 레지 보정 (Ledge Forgiveness)

- 하강 중 발끝이 발판 모서리에 살짝 걸치는 경우, 발판 위로 올려 주거나 착지로 인정한다.
- 올려 주는 최대 높이와 가로 허용 범위를 Inspector에서 조절한다.
- 벽에 붙어 오르는 동작처럼 보이지 않도록 모서리 근처 아주 작은 범위에서만 작동한다.

(3) 대시 코너 보정 (대시를 포함할 때만)

- 대시 중 지형 모서리에 걸리면 살짝 밀어서 통과시킨다.
- 코너 보정과 같은 방식으로 판정하고 별도 보정 거리를 둔다.

(4) 점프 정점 보정 (Apex Modifier)

- 상승에서 하강으로 바뀌는 정점 근처(수직 속도가 작은 구간)에서는 중력을 약하게 한다.
- 같은 구간에서는 좌우 이동 속도 또는 공중 가속도를 올려 발판 끝에 닿기 쉽게 한다.
- 적용 구간(수직 속도 임계값), 중력 배율, 가속 보너스를 Inspector에서 조절한다.
- 점프 컷과 하강 중력 배율([4])과 충돌하지 않도록 우선순위를 정한다. (정점 보정 구간에서는 하강 배율을 적용하지 않음)

(5) 보정 공통 규칙

- 보정은 이동 시스템 안에서 처리하고 상태 시스템과 애니메이션에는 결과만 전달한다.
- 보정이 일어나도 애니메이션이 튀거나 카메라가 흔들리지 않게 한다.
- 대시, 넉백 같은 외부 속도 중에는 어떤 보정을 적용할지 규칙을 정한다. (기본값: 코너 보정만 허용)

==================================================
[10. 구현 목표]
==================================================

1. 가속 / 감속 / 반대 입력 급정거가 되는 좌우 이동
2. 안정적인 지상 판정
3. 가변 점프 (짧게/길게, 키 뗐을 때 하강 가속)
4. 공중 방향 전환
5. 이동하면서 사격 (속도 배율, 조준 고정 옵션)
6. 대시/넉백 등 외부 속도와의 연동
7. 상태 시스템과 연동 (이동 허용 규칙)
8. Inspector에서 주요 수치 조절 가능
9. 기존 프로젝트 구조와 충돌하지 않는 구현
10. 월드 좌표를 하드코딩하지 않는 구현
11. 관용 시스템 (코너 보정, 레지 보정, 대시 코너 보정, 점프 정점 보정)
