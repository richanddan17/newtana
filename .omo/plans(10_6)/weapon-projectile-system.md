# Weapon & Projectile System Plan (Run & Gun)

Unity 2D 횡스크롤 총게임의 무기와 투사체 시스템을 구현해줘.
기존 Combat System의 "공격별 Damage 관리"와 "공격 흐름"을 이 문서가 대신한다.

먼저 현재 Player, Enemy, 기존 공격 스크립트, Collider2D 구조, 오브젝트 풀링 유무를 확인한 뒤 구현한다. 기존 구조와 충돌하지 않도록 필요한 부분만 수정한다.

플레이어와 적이 같은 무기/투사체 구조를 사용한다. (적 전용 사격 로직을 따로 만들지 않는다.)

==================================================
[1. 무기 데이터]
==================================================

무기는 데이터로 분리한다. (ScriptableObject 등 프로젝트에 맞는 방식)

필요한 정보:

- Damage
- 발사 간격 또는 초당 발사 수
- 발사 방식: 단발 / 연사 / 버스트 / 산탄
- 탄속, 사거리 또는 수명
- 탄 퍼짐(Spread)
- 관통 횟수 (0이면 관통 없음)
- 넉백 값
- 투사체 프리팹 참조
- 탄창 크기, 재장전 시간 (탄약을 사용할 때만)

공격(무기)마다 서로 다른 값을 사용할 수 있어야 하고, 이후 무기를 추가하기 쉬워야 한다.

==================================================
[2. 발사 흐름]
==================================================

입력 → 발사 가능 판단 → Muzzle 위치와 방향 계산 → 투사체 생성 → 쿨다운

발사 가능 판단:

- 상태 시스템이 사격을 허용하는가 (Hurt/Death/Dash 중 불가 등)
- 쿨다운이 끝났는가
- 탄약이 남아 있는가 (탄약 사용 시)
- 재장전 중이 아닌가

발사가 불가능한 순간에 들어온 사격 입력은 입력 시스템의 Shoot Buffer가 짧게 기억하고, 가능해지는 순간 이 흐름을 다시 시작한다.

발사 가능 여부와 연사 속도는 Weapon 시스템이 결정한다. 사격 애니메이션 길이가 발사 간격을 결정하지 않는다.

==================================================
[3. 조준과 Muzzle]
==================================================

- 조준 방향은 입력 시스템이 주는 값(방향 입력 또는 마우스/스틱)으로 계산한다.
- 방향 구간(정면/위/대각선 등)은 Inspector에서 설정할 수 있게 한다.
- 투사체는 Muzzle Transform 위치에서 생성한다.
- 캐릭터가 좌우를 바라보는 방향이 바뀌어도 Muzzle과 발사 방향이 함께 뒤집히도록 한다. (방향 전환 규칙은 animation-state-system.md 참고)
- 월드 좌표를 하드코딩하지 않는다.
- Muzzle이 벽 안쪽에 있을 때(벽에 바짝 붙어 쏠 때)의 처리 규칙을 정한다. (즉시 소멸 / 벽에 데미지 없음)

==================================================
[4. 투사체]
==================================================

투사체는 다음을 가진다.

- 소유자(Owner)와 Team: 플레이어 총알은 적만, 적 총알은 플레이어만 맞힌다.
- Damage 정보(DamageInfo): Damage, Attacker, Hit Direction, Knockback, Hit Type
- 이동: 직선 이동 (중력/유도 등은 확장 가능하게)
- 수명 또는 최대 사거리: 지나면 소멸
- 소멸 조건: Hurtbox 명중, 지형 충돌, 수명 종료, 화면/Room 밖

이동 방식:

- 빠른 총알이 벽을 뚫고 지나가는 현상(터널링)을 막는다. (이동 거리만큼 Raycast/Linecast를 쏘거나 Continuous 충돌을 사용)
- 투사체는 체력을 직접 조작하지 않고 DamageInfo를 대상의 Damage Receiver에 전달한다.

관통 총알:

- 같은 대상에게 한 발이 여러 번 데미지를 주지 않는다. (이미 맞힌 대상 목록 기록)
- 관통 횟수가 소진되면 소멸한다.
- 새로 발사된 총알은 새 목록을 사용한다.

==================================================
[5. 오브젝트 풀링]
==================================================

총알은 많이 생성되므로 Instantiate/Destroy 대신 풀링을 사용한다.

- 풀에서 꺼낼 때 상태(Team, Damage, 속도, 맞힌 목록)를 완전히 초기화한다.
- 풀로 돌려보낼 때 이동, 타이머, 이펙트를 정리한다.
- 풀 크기 부족 시 동작(확장 / 가장 오래된 총알 재사용)을 정한다.

==================================================
[6. 탄약과 재장전 (선택)]
==================================================

프로젝트에 탄약이 포함될 때만 구현한다. 처음에는 무한 탄약으로 시작해도 확장 가능한 구조로 만든다.

- 탄창, 예비 탄약, 재장전 시간
- 재장전 중 사격 불가, 재장전 취소 규칙
- 재장전 중 Hurt/Death가 오면 재장전을 안전하게 중단

==================================================
[7. 피드백 연결점]
==================================================

다음은 구현하지 않아도 연결할 수 있는 지점(이벤트)만 만든다.

- 발사 시: 머즐 플래시, 사운드, 탄피, 반동, 카메라 흔들림
- 명중 시: 히트 이펙트, 사운드, Hit Stop
- 소멸 시: 벽 충돌 이펙트

==================================================
[8. 정리와 예외]
==================================================

- 플레이어 사망/부활 시 쿨다운, 재장전, 연사 상태를 초기화한다.
- 발사자가 사망한 뒤 이미 날아가는 총알은 유지할지 제거할지 정한다. (기본값: 유지)
- 무기 교체가 있다면 교체 중 발사 규칙을 정한다.

==================================================
[9. 구현 목표]
==================================================

1. 무기 데이터 분리
2. 발사 흐름과 쿨다운 (애니메이션과 분리)
3. 조준과 Muzzle
4. 투사체 이동, 수명, 소멸
5. 터널링 방지
6. Team 필터와 DamageInfo 전달
7. 관통 총알의 중복 타격 방지
8. 오브젝트 풀링
9. 탄약/재장전 확장
10. 플레이어와 적 공용 구조
