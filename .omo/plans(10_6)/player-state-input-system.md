# Player State & Input System Plan (Run & Gun)

Unity 2D 횡스크롤 총게임의 플레이어 상태 시스템과 입력 처리를 구현해줘.

먼저 현재 Player 오브젝트, 기존 PlayerController, 입력 처리 방식(구 Input Manager / 새 Input System), 상태 관련 스크립트를 확인한다. 기존 구조와 충돌하지 않도록 필요한 부분만 추가하거나 수정한다.

이 문서는 플레이어 상태 우선순위의 "단일 출처"다. 이동, 애니메이션, 무기, 체력 문서는 상태 우선순위와 허용 규칙을 여기서 참조만 하고 따로 정의하지 않는다.

==================================================
[1. 상태 목록]
==================================================

이동 계열 상태 (동시에 하나만 활성):

- Idle
- Run
- Jump (상승)
- Fall (하강)
- Dash (대시가 프로젝트에 포함될 때만)
- Hurt
- Death

오버레이 (이동 계열 상태 위에 겹쳐 활성화될 수 있음):

- Shooting (사격 중)
- Reloading (재장전이 포함될 때만)

삭제된 상태: Attack, Combo Attack, Parry, Counter Attack.

==================================================
[2. 상태 우선순위]
==================================================

Death
→ Hurt
→ Dash
→ Jump / Fall
→ Run
→ Idle

높은 우선순위 상태는 낮은 상태로 들어갈 수 있는 입력을 막거나 덮어쓴다.
단, 현재 프로젝트의 실제 설계와 충돌하면 기존 설계를 기준으로 조정한다.

오버레이 규칙:

- Shooting은 Idle / Run / Jump / Fall 위에 겹칠 수 있다.
- Hurt, Death 중에는 Shooting이 해제된다.
- Dash 중 사격 가능 여부는 Inspector 옵션으로 둔다. (기본값: 불가)
- Hurt가 끝난 뒤 사격 입력이 계속 눌려 있으면 실제 입력 상태를 다시 판단해서 사격을 재개한다.

==================================================
[3. 상태별 허용 표]
==================================================

상태마다 "무조건 막는" 하드코딩을 하지 말고, 아래 허용 값을 상태 데이터로 관리한다.

| 상태 | 이동 | 점프 | 사격 | 대시 | 피격 가능 |
|---|---|---|---|---|---|
| Idle | O | O | O | O | O |
| Run | O | O | O | O | O |
| Jump/Fall | 공중 제어 | 코요테/버퍼 | O | 옵션 | O |
| Dash | 대시 속도 | X | 옵션 | X | 옵션(무적 프레임) |
| Hurt | 넉백 속도 | X | X | X | 무적 시간 동안 X |
| Death | X | X | X | X | X |

실제 값은 프로젝트에 맞게 조정하고, Inspector 또는 데이터로 수정할 수 있게 한다.

==================================================
[4. 상태 전환 규칙]
==================================================

- 모든 상태 변경은 한 곳(State Controller)을 통해서만 일어난다.
- 상태 전환 가능 여부는 현재 상태와 우선순위로 판단한다.
- 상태 종료 시 "무조건 Idle"로 돌아가지 말고 실제 조건(지상 여부, 입력, 속도)을 다시 판단한다.
- 상태가 바뀔 때 이벤트를 발생시켜 애니메이션, 이펙트, 사운드가 구독할 수 있게 한다. 상태 시스템이 애니메이션 쪽을 직접 호출하지 않는다.
- Death 상태에서는 다른 상태로 자동 전환하지 않는다. 복귀는 Checkpoint System만 요청할 수 있다.
- 부활 시 모든 상태와 입력 버퍼를 초기화하는 함수를 제공한다.

==================================================
[5. 입력 처리]
==================================================

입력은 게임 동작과 분리된 추상 입력으로 읽는다.

- 이동 축 (좌우)
- 조준 방향 입력 (위/아래/대각선, 또는 마우스/스틱)
- 점프
- 사격 (눌림 / 홀드 / 뗌)
- 대시 (포함 시)
- 재장전 (포함 시)

입력 장치(키보드, 패드)나 키 설정을 코드에 하드코딩하지 않는다.
입력 처리 스크립트는 값을 읽어 전달만 하고, 이동과 사격 로직은 각 시스템이 처리한다.

조준 방향 스냅 (Aim Snap):

- 대각선이나 위/아래 방향 입력이 애매할 때 가장 가까운 허용 방향(정면/위/대각선 등)으로 스냅한다.
- 방향 구간의 폭과 스냅 활성 여부를 Inspector에서 조절한다.
- 마우스/스틱 조준을 쓰는 경우에도 같은 구간 규칙을 적용할 수 있게 한다.
- 스냅 결과만 무기와 애니메이션에 전달하고, 입력 읽는 쪽이 계산을 흩어 놓지 않는다.

==================================================
[6. 입력 버퍼]
==================================================

버퍼는 입력 시스템 한 곳에서 관리하고 각 시스템이 가져다 쓴다.

- Jump Buffer: 착지 직전 점프 입력 기억 (시간 Inspector 조절, 활성/비활성 가능)
- Dash Buffer: 대시 입력 기억 (대시 포함 시)
- Shoot Hold: 연사 무기에서 누르고 있는 동안 계속 발사 요청
- Shoot Buffer: 쿨다운 중이나 발사 불가 상태에서 누른 사격 입력을 짧게 기억했다가, 가능해지는 순간 바로 발사한다. (버퍼 시간 Inspector 조절, 활성/비활성 가능)
- Reload / Weapon Swap Buffer: 불가능한 순간(발사 직후, Hurt 등)에 누른 재장전/무기 교체 입력을 짧게 기억했다가 가능해지면 실행한다. (재장전과 무기 교체가 포함될 때만)
- 버퍼는 상태 전환(Hurt, Death) 시 지우거나 유지하는 규칙을 명확히 한다. (기본값: Hurt/Death 시 초기화)

==================================================
[7. 입력 차단]
==================================================

다음 상황에서 입력을 차단하거나 무시할 수 있어야 한다.

- Death
- 컷신 / 대화 / 일시정지
- 부활 연출 중

차단 규칙은 상태 시스템에서 일관되게 처리한다.
