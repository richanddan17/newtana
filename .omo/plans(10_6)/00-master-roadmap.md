# Run & Gun Platformer - 종합 계획서 & 로드맵

Unity 2D 횡스크롤 총게임(Run & Gun) 전체 시스템 계획서의 구현 순서, 문서 현황, 공통 규약을 한곳에 정리한다.
패링 액션에서 총게임으로 장르가 바뀌었으므로 기존 7개 계획서를 새 방향에 맞춰 재분류했다.

==================================================
[1. 전제와 가정]
==================================================

확정된 방향:

- 장르: 2D 횡스크롤 총게임
- 근접/패링/콤보는 삭제

아직 확정되지 않은 사항 (아래 기본값으로 진행하고, 바뀌면 문서를 수정한다):

| 항목 | 기본 가정 | 영향받는 문서 |
|---|---|---|
| 사격 방식 | 눈에 보이는 투사체(Projectile) | weapon, hitbox, enemy-ai |
| 조준 | 방향 입력 기반 (정면/위/대각선). 마우스/8방향이면 확장 | animation, input, movement |
| 사격 중 이동 | 가능 (이동하면서 사격) | movement, animation |
| 대시 | 포함 여부 미정. 미정이면 선택 기능으로 둠 | movement, state, animation |
| 탄약/재장전 | 미정. 무한 탄약으로 시작해 확장 가능하게 | weapon |
| 피격 후 무적 | 짧은 무적 시간 포함 | health-damage |

[3. 공통 규약 (모든 문서가 따라야 하는 계약)]
==================================================

여러 문서가 같은 용어와 구조를 쓰도록 먼저 정한다.

1. DamageInfo: Damage, Attacker, Hit Direction, Knockback, Hit Type(총알/폭발/함정 등)
2. IDamageable(또는 Damage Receiver): 피격 대상은 DamageInfo를 받아 자기 Health에서 처리한다. 총알은 체력을 직접 건드리지 않는다.
3. Team / LayerMask: Player, Enemy, Neutral. 총알은 반대 팀만 맞힌다. 레이어 구성과 Collision Matrix를 한 번에 정한다.
4. Player State enum과 우선순위: 상태 우선순위는 player-state-input-system 한 곳에서만 정의하고 다른 문서는 참조만 한다.
5. WeaponData / ProjectileData: ScriptableObject 등 데이터로 분리해 플레이어와 적이 같은 구조를 쓴다.
6. 좌우 방향 규칙: 방향 전환은 한 곳에서 관리하고 Collider, Muzzle, 이펙트가 함께 따라간다.
7. 월드 좌표 하드코딩 금지. 위치는 Transform, 스포너, 체크포인트 오브젝트에서 가져온다.
8. 이동 Collider와 전투(Hurtbox) Collider 분리.

==================================================
[4. 구현 로드맵]
==================================================

각 단계는 앞 단계의 완료 기준을 만족한 뒤 시작한다.
모든 단계의 시작은 "현재 프로젝트의 기존 구조 확인"이다.

--------------------------------------------------
Phase 0. 기반 정리
--------------------------------------------------

- 위 [3. 공통 규약] 확정 (DamageInfo, Team/Layer, 인터페이스)
- 레이어와 Collision Matrix 설정
- 기존 프로젝트의 Player/Enemy/Collider 구조 파악
- 미확정 항목(사격 방식, 조준, 대시) 결정

완료 기준: 공통 규약 문서(또는 코드 스텁)가 존재하고, 이후 문서가 이를 참조한다.

--------------------------------------------------
Phase 1. 플레이어 상태와 입력
--------------------------------------------------

문서: player-state-input-system

- 상태 머신과 우선순위 (Death → Hurt → Dash → Jump/Fall → Run → Idle, 사격은 오버레이)
- 입력 버퍼 (점프, 대시, 사격, 재장전/무기 교체)
- 조준 방향 스냅
- 상태별 이동/사격 허용 표

완료 기준: 입력이 상태 머신을 통해 들어가고, 상태별 이동/사격 허용 여부가 한 곳에서 관리된다.

--------------------------------------------------
Phase 2. 플레이어 이동
--------------------------------------------------

문서: player-movement-system (수정본)

- 좌우 이동, 점프(Coyote/Buffer), 바닥 판정
- 이동하며 사격, 공중 사격
- 대시(포함 시)와 넉백 시 이동 입력 잠금
- 관용 시스템: 코너 보정, 레지 보정, 대시 코너 보정, 점프 정점 보정

완료 기준: 이동/점프/낙하가 안정적이고, 상태 시스템과 연동되어 상태별 이동 제한이 동작한다.

--------------------------------------------------
Phase 3. 플레이어 애니메이션
--------------------------------------------------

문서: animation-state-system (v2)

- Animator 파라미터 연동, 사격 오버레이, 조준 방향
- 방향 전환 규칙 (Collider/Muzzle 포함)

완료 기준: 이동 상태와 사격이 겹쳐 올바르게 재생되고, 방향을 바꿔도 Muzzle 위치가 맞다. (이 시점에서는 총알이 없어도 된다.)

--------------------------------------------------
Phase 4. 무기, 투사체, 판정, 체력
--------------------------------------------------

문서: weapon-projectile-system, hitbox-hurtbox-system, health-damage-system

- 무기 데이터, 발사 속도, Muzzle 발사, 투사체 이동/수명/풀링
- 투사체와 Hurtbox 판정, Team 필터, 지형 충돌
- DamageInfo 전달, Health 처리, 피격 무적, 사망 이벤트
- 중복 타격 방지 (관통 총알일 때)

완료 기준: 플레이어가 쏜 총알이 더미 타겟에 정확히 한 번 데미지를 주고, 지형에서 사라지며, 사망까지 처리된다.

--------------------------------------------------
Phase 5. 적 AI
--------------------------------------------------

문서: enemy-ai-system (v2)

- 상태 기반 AI, 시야 감지, 거리 유지, 낭떠러지/벽 감지
- 조준 → 예고 → 사격 → 쿨다운
- 피격(누적 경직)과 사망(비활성화 기반)

완료 기준: 적 한 종류가 플레이어를 감지해 접근/조준/사격하고, 맞으면 반응하며 죽는다. 같은 AI에 데이터만 바꿔 두 번째 적을 만들 수 있다.

--------------------------------------------------
Phase 6. 플레이어 피격과 적 애니메이션 정리
--------------------------------------------------

- 플레이어 Hurt/Death 연동 최종 점검
- 적 애니메이션을 같은 원칙으로 연결 (Aim/Shoot/Hurt/Dead)
- 피격 피드백 (Hit Flash, 사운드), 필요 시 Hit Stop

완료 기준: 서로 쏘고 맞는 전체 전투 루프가 애니메이션과 함께 자연스럽게 돈다.

--------------------------------------------------
Phase 7. Room, 카메라, 체크포인트
--------------------------------------------------

문서: room-camera-system, checkpoint-respawn-system

- Room 경계와 카메라 전환
- 체크포인트 활성화, 사망 → 부활, 상태 초기화
- 적 리셋 정책 (Room 기준), 부활 후 무적과 카메라 Room 갱신
- 낙사/함정 사망 처리와 낙사 구제 (가장자리 구제, 즉시 부활)

완료 기준: 사망 후 마지막 체크포인트에서 부활하고, 카메라가 올바른 Room을 사용하며, 적 리셋 정책이 동작한다.

--------------------------------------------------
Phase 8. 확장과 마감
--------------------------------------------------

- 적 유형 추가 (터렛, 근접, 비행)
- 무기 종류 추가, 탄약/재장전
- 보스 패턴 (필요 시)
- 밸런싱과 Inspector 값 정리, 성능 점검 (풀링, 동시 사격 제한)

==================================================
[5. 단계별 의존 관계]
==================================================

Phase 0 → Phase 1 → Phase 2 → Phase 3
Phase 1 → Phase 4 (상태 시스템이 사격 허용 여부를 결정)
Phase 3 + Phase 4 → Phase 5 → Phase 6
Phase 4 + Phase 5 → Phase 7

Phase 3(애니메이션)과 Phase 4(무기)는 Muzzle 규칙에서 만난다. Muzzle과 방향 전환 규칙은 Phase 3에서 정하고 Phase 4가 그대로 사용한다.

==================================================
[6. 이전 검토에서 나온 위험 요소의 처리 위치]
==================================================

| 위험 요소 | 처리 위치 |
|---|---|
| 상태 우선순위 충돌 | Phase 1에서 단일 출처로 통합 |
| Combat/Hitbox 문서 중복 | weapon-projectile(생성/수명)과 hitbox-hurtbox(판정)로 역할 분리 |
| 적 제거 vs 적 리셋 충돌 | enemy-ai에서 비활성화 기반으로 변경, checkpoint와 연결 |
| flipX와 Collider/Muzzle | animation v2 [8]에서 규칙 정의 |
| Animation Event 누락 시 상태 고착 | animation v2 [5]에서 안전장치 요구 |
| 피격 후 무적 없음 | health-damage에서 정의, checkpoint의 부활 무적과 연결 |
| Hit Stop/VFX/SFX 소유자 없음 | Phase 6에서 확장 포인트로 처리 |
| 대시 포함 여부 모호 | Phase 0에서 결정 |

==================================================
[7. 작업 방식 (Claude Code 등에 투입할 때)]
==================================================

1. 문서를 한 번에 하나씩 투입한다. 순서는 Phase 번호를 따른다.
2. 각 투입의 첫 지시: "이 종합 계획서의 [3. 공통 규약]을 먼저 읽고 따른다."
3. 한 Phase가 끝나면 완료 기준을 직접 확인한 뒤 다음 Phase로 넘어간다.
4. 이전 Phase에서 만든 코드를 수정해야 하면, 문서를 다시 쓰지 말고 영향받는 부분만 수정 요청한다.
5. 새 문서를 쓸 때는 항상 "먼저 현재 프로젝트 확인" 단계를 첫 줄에 넣는다.

==================================================
[8. 지금 결정이 필요한 것]
==================================================

1. 사격이 투사체인가, 즉시 판정(히트스캔)인가
2. 조준이 좌우 고정 + 위/대각선인가, 8방향인가, 마우스 조준인가
3. 대시를 넣을 것인가
4. 탄약과 재장전을 처음부터 넣을 것인가
5. 플레이어 스프라이트가 통짜인가, 상체/하체 분리인가

에셋 팩(Generic Run'n'Gun Pack) 기준으로 확정된 사항:

- 조준은 3방향(정면/위/공중 아래), 대각선 없음
- 플레이어는 통짜 스프라이트이므로 이동+사격을 합친 클립을 사용
- 앉기(Crouch)는 포함, 대시와 재장전은 에셋에 없어 기본 비활성
- 전용 Hurt 클립 없음 (피격 플래시로 처리)
- 적은 AR(이동+3방향 사격), RPG(고정, 폭발), Sniper(고정, 정면 저격) 3종
- 로켓 폭발은 범위 피해이므로 hitbox-hurtbox의 범위 공격과 health-damage의 폭발 Hit Type 사용
- 이에 따라 player-state-input, player-movement, weapon-projectile, hitbox-hurtbox 문서에 앉기 상태와 3방향 조준 반영 필요
