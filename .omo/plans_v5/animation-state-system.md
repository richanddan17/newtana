# Animation State System Plan (v5 - player_1 기준, 단일 몸통 + VFX 레이어)

Unity 6 2D 횡스크롤 액션게임의 플레이어 애니메이션 상태 시스템을 구현해줘.

먼저 현재 Animator Controller, Animation Clip, Sprite 구조, 기존 스크립트를 확인한다. 스프라이트 규격(셀 크기, pivot, 프레임 수)은 sprite-asset-spec.md를 따른다.

이 문서는 플레이어 애니메이션을 다룬다. 적 애니메이션은 enemy-ai-system.md에서 같은 원칙으로 처리한다.

v5에서 바뀐 점:
- 플레이어 에셋이 Bot Wheel(Body/Arm 분리, 총)에서 player_1(몸통 한 장 + 이펙트 별도)로 바뀌었다. Body/Arm 구조, AimDir 5방향, Muzzle 표는 삭제한다.
- 모든 시트는 "한 사이클만" 남긴 버전을 쓴다. (원본은 GIF 반복을 그대로 변환한 시트였음)
- 캐스트는 몸 시트 `19_cast` 하나만 쓰고, 단계별 이펙트는 vfx 시트를 얹어서 만든다. (cast_basic / cast_rapid / cast_big 몸 시트는 쓰지 않는다.)

확인되지 않은 것은 문서 끝 [10]에 모아둔다. 본문의 값은 "시트 분석으로 확인한 값"과 "이 문서가 정한 기본값"을 구분해서 적는다.

==================================================
[1. 구조]
==================================================

Player (루트, scale.x로 좌우 반전)
 ├ Body   : SpriteRenderer + Animator (몸 전체. 공격, 캐스트 포함)
 ├ CastFX : SpriteRenderer + 스크립트 (캐스트 이펙트 시퀀스)
 └ AuraFX : SpriteRenderer (선택, 06_aura)

- 몸은 한 오브젝트(Body)가 전부 담당한다. 공격/캐스트/활도 몸 시트에 들어 있으므로 팔을 따로 분리하지 않는다.
- 이펙트는 몸과 분리된 별도 오브젝트로 둔다. (몸 클립을 늘리지 않고 이펙트 단계만 바꾸기 위해)
- 좌우 반전은 루트 scale.x = -1. SpriteRenderer.flipX는 쓰지 않는다. (Collider, 히트박스, 이펙트 위치가 안 뒤집힘)
- Avatar Mask는 쓰지 않는다.

[2. 상태 목록]
==================================================

시트 이름을 기준으로 정리한다. 프레임 수는 한 사이클만 남긴 값이다. (sprite-asset-spec.md 참고)

이동 계열:
- Idle (01_idle, 28프레임, 루프)
- Run (02_run, 10프레임, 루프)
- Jump / Fall (03_jump_and_fall, 28프레임 한 장. 상승/하강 분할 지점 미확인, [10] 참고)
- DoubleJump (04_double_jump, 14프레임, 1회)
- Dash (05_dash, 5프레임)
- WallSlide (06_wall_slide, 32프레임, 루프)
- Climb (07_climb, 9프레임, 루프)
- Crouch (08_crouch, 5프레임)
- EnterDoor (09_enter_door, 15프레임, 1회)
- Grapple (10_grapple, 8프레임)

공격 계열:
- Attack1 / Attack2 / Attack3 (11: 8프레임, 12: 5프레임, 13: 10프레임) - 콤보
- JumpAttack (14, 9프레임)
- UpAttack (15, 7프레임)
- DownAttack (16, 7프레임)
- HeavyAttack (17, 11프레임)
- Bow (18, 22프레임)
- Cast (19_cast, 11프레임) + CastFX (6번 항목)

피격 계열:
- Hurt (20_hurt, 7프레임)
- HurtKnockback (21_hurt_knockback, 8프레임)
- Death (22_death, 22프레임, 마지막 프레임 유지)

사용하지 않는 시트: 23_cast_basic, 24_cast_rapid, 25_cast_big (캐스트는 19_cast + vfx로 대체).

선택 상태는 게임에 실제로 넣는 기능만 연결한다. 시트가 있다는 이유만으로 상태를 강제로 만들지 않는다.
(Crouch, Grapple, WallSlide, Climb, EnterDoor, DoubleJump, Bow, HeavyAttack은 해당 기능을 플레이어 이동/상태 문서에서 넣기로 정했을 때만 연결한다.)

==================================================
[3. 로직 상태와 Animator 분리]
==================================================

게임 로직이 현재 상태를 판단하고, Animator에는 필요한 파라미터만 전달한다.
Animator 상태 구조를 로직 상태 구조와 똑같이 강제하지 않는다.

Animator 파라미터:
- Speed (float, 수평 속도 절댓값)
- VelocityY (float)
- IsGrounded (bool)
- IsWallSliding (bool)
- IsDashing (bool)
- AttackIndex (int, 콤보 단계 0~3)
- Hurt (trigger), HurtKnockback (trigger)
- IsDead (bool)
- Cast (trigger), Bow (trigger) 등 일회성 동작은 trigger

애니메이션은 "읽기만" 하고 이동/공격 로직을 직접 호출하지 않는다.
상태 시스템이 보내는 상태 변경 이벤트를 구독해서 반응한다. (player-state-input-system [4] 참고)

우선순위(피격 > 대시 > 공격 > 이동 등)는 이 문서에 다시 적지 않는다. player-state-input-system.md [2]를 따른다.

==================================================
[4. 루프 / 1회 재생 규칙]
==================================================

Animation Clip의 Loop Time 기준:

| 구분 | 상태 |
|---|---|
| 루프 | Idle, Run, WallSlide, Climb |
| 1회 | 공격 전체, Cast, Bow, Dash, DoubleJump, EnterDoor, Grapple, Hurt, HurtKnockback |
| 1회 후 마지막 프레임 유지 | Death |

- 공격/캐스트처럼 1회 재생 상태가 끝나면 무조건 Idle로 가지 않는다. 그 시점의 실제 상태(지상/공중, 입력)를 다시 판단한다.
- 루프 시트는 첫 프레임과 마지막 프레임 이음새가 자연스러운지 눈으로 확인한다. (사이클 길이를 자동 탐지했으므로 [10] 참고)
- Sample Rate는 원본 GIF의 프레임 간격이 시트에 남아 있지 않으므로 기본 12로 시작해 상태별로 조정한다. (미확인 값)

==================================================
[5. 공격과 판정 타이밍]
==================================================

공격 애니메이션 길이와 실제 판정 시점을 같은 것으로 취급하지 않는다.

- 판정(히트박스)이 켜지는 프레임과 꺼지는 프레임은 각 공격 클립 안에서 Animation Event 또는 프레임 번호 표로 정한다. 값은 hitbox-hurtbox-system.md에서 관리한다.
- 콤보 입력 허용 시간(윈도우)은 공격 클립의 후반 프레임 구간으로 정한다. 윈도우 안에서 입력이 들어오면 다음 공격으로, 아니면 Idle 판단으로 간다.
- Animation Event를 쓰는 경우 클립이 중간에 끊겨도(피격 등) 판정이 켜진 채 남지 않도록, 상태를 나갈 때 히트박스를 반드시 끈다.
- 공중 공격(JumpAttack)은 착지 시 클립을 끊을지 끝까지 재생할지 정한다. (기본값: 착지해도 재생 유지, 이동만 허용)
- UpAttack/DownAttack은 입력 방향이 있을 때만 들어간다. 입력 규칙은 player-state-input-system.md에서 정한다.

==================================================
[6. 캐스트와 VFX 조합]
==================================================

몸은 `19_cast` 하나, 이펙트는 vfx 시트를 단계별로 얹는다.

기본 캐스트:
1. 모으기: 01_gather (25프레임) 재생
2. 유지: 02_charge_loop (루프) - 버튼을 누르고 있는 동안
3. 발사: 03_release

큰 캐스트(차지 완료 등 조건에서만):
1. 04_big_loop (루프)
2. 05_big_release

- 06_aura는 캐스트 중 또는 버프 상태 표시용 선택 오버레이다.
- 단계 전환은 CastFX 스크립트가 맡는다. Body Animator는 Cast 상태만 알고, 이펙트 단계는 모른다.
- 몸 Cast 클립의 어느 프레임에서 이펙트가 시작/발사되는지 프레임 번호를 정해서 맞춘다. (미확인, [10])
- 이펙트 위치는 손 앞 기준점(CastPoint, Body의 자식 빈 Transform)에 붙인다. 몸 프레임마다 손이 움직이면 CastPoint를 클립에서 키로 움직이거나 프레임 표를 쓴다.
- 캐스트가 피격 등으로 중단되면 CastFX를 즉시 끄고 단계를 초기화한다.
- 큰 캐스트와 기본 캐스트의 몸 동작은 같다. 차이는 이펙트 단계와 데미지/연출뿐이다. (weapon-projectile-system과 연결)

==================================================
[7. 피격 / 사망]
==================================================

- Hurt: 일반 피격, HurtKnockback: 넉백이 있는 피격. 어느 쪽을 쓸지는 health-damage-system의 피격 종류로 정한다.
- 피격 시 진행 중인 공격/캐스트/활을 중단하고, 히트박스와 CastFX를 끈다.
- 피격 애니메이션이 끝나도 무조건 Idle로 가지 않고 실제 상태를 다시 판단한다.
- 짧은 연속 피격에서 Hurt가 계속 재시작되어 멈춘 것처럼 보이지 않도록 무적 시간과 연동한다.
- 피격 깜빡임은 별도 컴포넌트가 Body(와 켜져 있는 FX)에 적용한다.
- Death: 판정과 애니메이션을 분리한다. 진입 후 자동 전환 없음. 부활은 Checkpoint System이 처리한다.

==================================================
[8. 피벗과 프레임 안정성]
==================================================

- 시트마다 셀 크기가 다르다. (sprite-asset-spec.md 표) 모든 상태에서 "발 위치"가 월드에서 같은 점에 오도록 시트별 Custom Pivot을 따로 맞춘다.
- 피벗이 어긋나면 상태가 바뀔 때 캐릭터가 위치가 튄다. 시트를 Unity에 넣은 뒤 Idle과 Run을 겹쳐 놓고 확인한다.
- 애니메이션별로 스케일을 바꿔서 캐릭터 크기가 튀지 않게 한다.
- 공격처럼 셀이 넓은 시트는 몸이 아니라 무기/궤적까지 포함해서 셀이 커진 것이다. Collider와 Hurtbox는 Idle 기준 몸통에 고정하고 시트 크기를 따라가지 않는다.

==================================================
[9. 구현 목표]
==================================================

1. Body 단일 오브젝트 + CastFX/AuraFX 구조
2. 상태별 Animation Clip (한 사이클 시트 기준, 루프/1회 규칙 적용)
3. Animator 파라미터 연동 (우선순위는 state 문서 참조)
4. 콤보 공격 연결과 판정 프레임 연동
5. 캐스트 몸 + 이펙트 단계 시퀀스
6. Hurt/Death 연동과 중단 시 정리(히트박스, FX)
7. 시트별 pivot 정렬
8. 방향 전환 (루트 scale.x)
9. 현재 프로젝트의 애니메이션 구조 최대한 유지

[10. 아직 확인되지 않은 것]

- 원본 GIF 프레임 간격(재생 속도)
- Cast 몸 프레임과 이펙트 시작/발사 프레임 번호, 손 위치(CastPoint)
- Dash 방향(시트 기준 방향), 공격 시트의 판정 프레임 번호
