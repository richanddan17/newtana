# Animation State System Plan (v4 - Unity 6, Body/Arm 분리)

Unity 6 2D 횡스크롤 총게임의 플레이어 애니메이션 상태 시스템을 구현해줘.

먼저 현재 Animator Controller, Animation Clip, Sprite 구조, 기존 스크립트를 확인한다. 스프라이트 규격(셀 크기, pivot, 앵커, Muzzle 값)은 sprite-asset-spec.md를 따른다.

이 문서는 플레이어 애니메이션을 다룬다. 적 애니메이션은 enemy-ai-system.md에서 같은 원칙으로 처리한다.

v2에서 바뀐 점: 스프라이트 구조가 "상체/하체 분리(Body + Arm)"로 확정되었고, 조준 방향은 5방향 스냅으로 확정되었다. Crouch는 이 프로젝트에 포함하지 않는다.

==================================================
[1. 구조 (확정)]
==================================================

플레이어 비주얼은 Body와 Arm 두 오브젝트로 나눈다.

Player (루트, scale.x로 좌우 반전)
 ├ Body  : SpriteRenderer + Animator (몸통 애니메이션)
 └ Arm   : SpriteRenderer (총 + 손, 조준 방향별 스프라이트를 스크립트로 교체)
     ├ Muzzle   : 빈 Transform (총알 생성 위치)
     └ MuzzleFX : SpriteRenderer (총구 이펙트)

- Body는 팔(총)이 없는 몸통만 그린 스프라이트를 쓴다. 총은 Arm이 담당한다.
- "Run+Shoot", "Jump+Shoot" 같은 합본 클립은 만들지 않는다. (Body 상태 × 조준 방향 조합이 곱셈으로 늘어나는 것을 막기 위한 결정)
- Avatar Mask는 사용하지 않는다. (2D 스프라이트에서는 통하지 않고, 오브젝트 분리 구조로 대신한다.)
- Arm은 Animator가 아니라 스크립트(PlayerArm)가 스프라이트를 교체한다. 조준 방향은 값으로만 받는다.

==================================================
[2. 상태 목록]
==================================================

Body 상태:

- Idle
- Run
- Jump (상승)
- Fall (하강)
- Hurt
- Death

선택 상태 (프로젝트에 클립이 실제로 있을 때만):

- Dash
- Wake (부활 연출, 5프레임)
- Charge (차지샷을 넣을 때만)
- Reload (재장전을 넣을 때만)

사격(Shoot)은 독립된 상태가 아니라 Arm 쪽 오버레이다. (3번 항목 참고)

삭제된 상태: Parry, Counter Attack, Combo Attack, 근접 Attack, Crouch.

현재 프로젝트에 실제 존재하는 애니메이션만 사용하고 없는 상태는 새로 강제 생성하지 않는다.

==================================================
[3. 로직 상태와 Animator 분리]
==================================================

게임 로직이 현재 상태를 판단하고, Animator에는 필요한 파라미터만 전달한다.
Animator 상태 구조를 로직 상태 구조와 똑같이 강제하지 않는다.

Animator 파라미터 (Body용):

- Speed (float, 수평 속도 절댓값)
- VelocityY (float)
- IsGrounded (bool)
- IsDashing (bool, 대시가 있을 때)
- Hurt (trigger)
- IsDead (bool)

AimDir과 IsShooting은 Animator 파라미터가 아니다. Arm 스크립트가 직접 받는다. (4, 5번 항목 참고)

애니메이션 전환 스크립트와 이동/사격 로직은 서로 강하게 결합하지 않는다.
애니메이션 쪽은 "읽기만" 하고 이동/사격 로직을 직접 호출하지 않는다.
상태 시스템이 보내는 상태 변경 이벤트를 구독해서 반응한다. (player-state-input-system [4] 참고)

==================================================
[4. 우선순위와 Arm 표시 규칙]
==================================================

Body의 상태 우선순위는 이 문서에 다시 적지 않는다. player-state-input-system.md [2]를 따른다.
(여러 문서에 복사하면 한쪽만 고쳤을 때 어긋나기 때문)

Arm 표시 규칙 (기본값):

| Body 상태 | Arm | 사격 연출 |
|---|---|---|
| Idle / Run / Jump / Fall | 표시 (조준 자세) | 가능 |
| Hurt | 숨김 | 중단 |
| Death | 숨김 | 중단 |
| Dash | 숨김 (Dash 중 사격 옵션이 켜지면 표시) | 옵션 |
| Wake | 숨김 | 불가 |

- Hurt에서 돌아온 뒤 사격 입력이 계속 눌려 있으면 실제 입력 상태를 다시 판단해서 Arm을 다시 표시하고 사격을 재개한다.
- 사격 중이 아니어도 Arm은 조준 자세(사격 4프레임 중 마지막 프레임)를 유지한다. (기본값)
- 확장 옵션: 사격하지 않을 때 총을 내린 자세(run_carry, idle_carry 풀바디 스프라이트)로 바꾸는 방식. 기본 구현에는 넣지 않는다.

==================================================
[5. 조준 방향 (5방향 확정)]
==================================================

조준 방향 계산과 스냅은 입력 시스템(player-state-input-system [5])이 하고, 애니메이션은 결과값(AimDir)만 받는다.

AimDir 값:

| 값 | 방향 | 스프라이트 |
|---|---|---|
| 0 | 정면 | arm_front |
| 1 | 위 45° | arm_up45 |
| 2 | 위 90° | arm_up90 |
| 3 | 아래 45° | arm_down45 |
| 4 | 아래 90° | arm_down90 |

- 왼쪽 조준은 별도 스프라이트 없이 루트 scale.x = -1로 처리한다.
- 아래 방향은 공중에서만 허용하는 것이 기본값이다. (지상에서는 정면으로 스냅. 옵션은 input 문서 참고)
- 방향마다 Arm 스프라이트 세트가 있다: 사격 4프레임 + 총구 이펙트 4프레임.
- 없는 조준 방향 스프라이트를 억지로 만들지 않는다. 가장 가까운 존재하는 방향으로 대체한다.
- 방향이 바뀌면 Arm 스프라이트와 Muzzle 위치를 같은 프레임에 같이 교체한다. (한 프레임이라도 어긋나면 총알이 엉뚱한 곳에서 나간다.)

==================================================
[6. 사격 연출과 발사 타이밍]
==================================================

사격 연출 길이와 실제 발사 시점, 발사 가능 여부를 같은 것으로 취급하지 않는다.

- 발사 가능 여부, 연사 속도, 탄약은 Weapon 시스템이 결정한다.
- Weapon이 "발사됨" 이벤트(OnFired)를 보내면, Arm이 PlayShot()으로 연출만 재생한다. (사격 4프레임 + 총구 이펙트 4프레임)
- 연출은 스크립트(코루틴 등) 기반이므로 Animation Event가 필요 없다. 이벤트 누락으로 상태가 고착되는 문제가 없다.
- 연사 간격이 연출 길이(기본 4프레임 × 0.06초 = 0.24초)보다 짧으면, 새 발사 때 연출을 처음부터 다시 재생하거나 마지막 2프레임만 재생하는 규칙을 정한다. 연사 중 팔이 계속 떨리지 않도록 한다.
- 연출이 끝나면 조준 자세로 복귀한다. 중간에 방향이 바뀌어도 새 방향 스프라이트로 이어서 재생한다.

총구(Muzzle):

- 총알이 나가는 위치는 Muzzle Transform 기준이다. Muzzle은 Arm의 자식이다.
- 방향마다 총구 위치가 다르므로, 방향이 바뀔 때 Muzzle의 localPosition을 sprite-asset-spec.md의 표에서 가져와 갱신한다.
- 좌우 반전은 루트 scale.x로 하므로 Muzzle도 자동으로 뒤집힌다.
- 월드 좌표를 하드코딩하지 않는다.

==================================================
[7. Arm 위치와 몸 흔들림]
==================================================

달리기 등 Body 프레임마다 몸이 위아래로 움직이므로 Arm 위치도 같이 움직여야 한다.

- Arm의 localPosition은 Body 프레임별 앵커 값(sprite-asset-spec.md 표)을 따른다.
- 권장: Run, Idle, Jump, Fall 클립 안에서 Arm의 localPosition에 키를 찍는다. (Body 프레임과 동기화되어 어긋나지 않음)
- 대안: 스크립트가 Body의 현재 스프라이트(프레임 번호)를 읽어 표에서 위치를 적용한다.
- 보정이 일어나도 Arm이 몸에서 떨어져 보이거나 튀지 않게 한다.

==================================================
[8. 피격 / 사망 애니메이션]
==================================================

피격 애니메이션 재생 중 이동/사격 가능 여부를 Player State System과 연결한다.

- Hurt 진입 시 Arm을 숨기고, 사격 연출을 중단한다.
- 피격 애니메이션이 끝났다고 무조건 Idle로 전환하지 말고 실제 게임 상태(지상/공중, 입력)를 다시 판단한다.
- 짧은 연속 피격에서 Hurt가 계속 재시작되어 애니메이션이 멈춘 것처럼 보이지 않도록 한다. (무적 시간과 연동)
- 피격 시 깜빡임(Flash/Blink)은 별도 컴포넌트로 처리하며 Body와 Arm에 함께 적용한다.

사망:

- 사망 판정과 사망 애니메이션을 분리한다.
- Death 진입 후에는 다른 상태로의 자동 전환이 일어나지 않는다. (부활은 Checkpoint System이 처리)
- Death 중에는 Arm이 숨겨진 상태를 유지한다.

==================================================
[9. 애니메이션 프레임]
==================================================

Sprite 애니메이션은 Unity의 Animation Clip과 Sprite Renderer 구조를 기준으로 관리한다.

- 매 프레임 Update에서 이미지를 직접 교체하는 방식은 Body에는 사용하지 않는다. (Arm의 방향 교체와 사격 연출은 예외)
- Run은 Sample Rate 10 정도, Loop Time을 켠다. 필요하면 Sample Rate와 프레임 타이밍을 조정한다.
- 모든 Body 스프라이트는 같은 pivot을 쓴다. 다르면 애니메이션이 떨린다.

==================================================
[10. 방향 전환 (확정)]
==================================================

바라보는 방향의 규칙은 한 곳에서 정한다: player-state-input-system.md [5]의 "바라보는 방향" 규칙을 따른다.
(기본값: 조준 방향 우선. 조준 입력의 좌우 성분이 있으면 그쪽, 없으면 이동 방향, 둘 다 없으면 유지)

- 루트의 scale.x를 반전한다. Body, Arm, Muzzle, Collider 오프셋이 함께 뒤집힌다.
- SpriteRenderer.flipX는 사용하지 않는다. (Collider와 Muzzle이 안 뒤집힌다.)
- 애니메이션별로 스케일을 임의로 변경하여 캐릭터 크기가 튀는 문제가 발생하지 않도록 한다.
- Arm의 Sorting Order는 Body보다 높게 둔다. (팔이 몸통 앞에 그려지도록)

==================================================
[11. 구현 목표]
==================================================

1. Body/Arm 오브젝트 구조
2. Body 상태 정리와 Animator 파라미터 연동 (우선순위는 state 문서 참조)
3. Arm 방향 교체 (5방향)와 표시/숨김 규칙
4. 사격 연출 (발사 타이밍은 Weapon이 결정, 연출은 OnFired로 재생)
5. 방향별 Muzzle 위치 갱신
6. Body 프레임별 Arm 위치 동기화
7. Hurt/Death 연동 (Arm 숨김)
8. Dash/Wake/Charge/Reload 연동 (존재할 때만)
9. 방향 전환 (루트 scale.x, Collider/Muzzle 포함)
10. 현재 프로젝트의 애니메이션 구조 최대한 유지
