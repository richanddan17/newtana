# Background / Parallax System Plan (v1 - Room 단위 배경 + 카메라 속도 비율)

Unity 6 2D 횡스크롤 총게임의 배경(패럴랙스) 시스템을 구현해줘.

카메라와 Room 구조는 room-camera-system.md를 따른다. 배경 에셋 규격은 sprite-asset-spec.md와 아래 [2] 표를 따른다.

==================================================
[0. 현재 상태]
==================================================

- 배경 스프라이트 에셋만 존재한다. (Assets/sprite/background/)
  - subway/subway_BG.png 496×272px (4.96 × 2.72 유닛 @ PPU 100)
  - subway/wall_subway.png 560×696px (5.60 × 6.96 유닛)
  - nuvens/nuvens_1~3.png 각 496×272px (3장 레이어용)
  - 임포트 설정은 플레이어/적과 동일(PPU 100, Point, Multiple)
- 패럴랙스 스크립트 0개. SampleScene에 배경 오브젝트 0개. 플랜 문서 최초.
- 카메라: RoomCamera가 플레이어를 추적하고 Room 경계(Bounds Collider)로 클램프하며,
  Room 전환 시 Lerp 이동한다. (RoomCamera.cs)
- Room: BoxCollider2D 기반 경계 + OnRoomChanged 이벤트. (Room.cs, RoomManager.cs)

==================================================
[1. 구조 (확정)]
==================================================

배경은 **Room 단위로 배치**한다. 공통 배경을 씬 하나에 두고 전역으로 흔들면
Room 전환 연출(카메라 Lerp)과 어긋나기 때문이다.

RoomX
 ├ (기존) Bounds Collider / Tilemap / Enemies / Checkpoints
 └ Background
     ├ BG_Main    : Subway 배경 (SpriteRenderer + ParallaxLayer)
     ├ BG_Front   : wall_subway (SpriteRenderer + ParallaxLayer, 옵션)
     └ Clouds
         ├ nuvens_3 (ParallaxLayer, 가장 느리게)
         ├ nuvens_2
         └ nuvens_1 (구름 중 가장 빠르게)

- 배경 전용 스크립트는 ParallaxLayer 하나만 만든다. (단일 책임)
- ParallaxLayer는 카메라 위치를 읽어 자신의 위치를 보정한다. 카메라를 직접 움직이지 않는다.
- Z오프셋 대신 Sorting Layer/Order로 앞뒤를 정한다. (URP 2D Renderer)

==================================================
[2. 레이어 설계와 에셋 매핑]
==================================================

속도 계수 factor = 카메라 이동에 대한 배경 반응 비율. 0에 가까울수록 멀리(거의 고정), 1이면 카메라와 동일(=고정 배경처럼 보임).

| 레이어 | 에셋 | factor X | factor Y | Sorting | 용도 |
|---|---|---|---|---|---|
| BG_Sky | nuvens_3 | 0.10 | 0.05 | BG_Far, order 0 | 하늘/가장 먼 층 |
| BG_Cloud2 | nuvens_2 | 0.20 | 0.10 | BG_Far, order 1 | 중간 구름 |
| BG_Cloud1 | nuvens_1 | 0.35 | 0.15 | BG_Far, order 2 | 가까운 구름 |
| BG_Main | subway_BG | 0.70 | 0.50 | BG_Main, order 0 | 지하철 본 배경 |
| BG_Front | wall_subway | 1.00 | 1.00 | FG, order 0 (플레이어 앞) | 전경 벽 겹침 (선택) |

- 위 숫자는 시작값이다. Inspector에서 조정 가능하게 열어두고 플레이로 확정한다.
- wall_subway는 화면 앞쪽을 가리는 전경으로 쓰는 것이 자연스럽다(높이 6.96유닛).
  전경으로 쓰지 않으면 패럴랙스를 끄고 BG_Main 뒤에 그대로 깐다.
- 구름은 방 경계를 넘어 자연스럽게 이어지도록 배경 폭을 넉넉히 잡는다. ([4] 참고)

Sorting Layer (프로젝트 설정에 새로 만든다):

  BG_Far < BG_Main < Default(플레이어/적) < FG < UI

==================================================
[3. ParallaxLayer 스크립트 규칙]
==================================================

핵심 공식 (Room 전용 카메라에 맞는 형태):

  배경 위치 = 방 중심 + (카메라 위치 - 방 중심) × (1 - factor)

- 카메라가 방 중심에 있으면 배경도 방 중심. 카메라가 방 가장자리로 가면 배경이
  factor 비율만큼만 따라 움직인다. (전역 cam×factor 공식은 방 클램프 카메라에서 배경이 방을 벗어난다.)
- factor X와 Y는 서로 독립이다. (구름은 수평만 움직이게 등)
- 방 중심 참조: ParallaxLayer가 붙은 Background 오브젝트의 초기 위치를 기준 오프셋으로 캐시한다.
  (Room 자식이므로 그 위치가 방 배경 기준점이 된다)

구현 규칙:

- 갱신 시점은 LateUpdate. 카메라(RoomCamera)보다 뒤에 실행되도록 Script Execution Order을 늦추거나,
  1프레임 지연이 눈에 띄면 OnCameraMoved 콜백을 RoomCamera에 추가하는 방식으로 해결한다. (기본은 실행 순서 조정)
- 카메라 위치는 Camera.main.transform.position 그대로 쓴다. (LookAhead·전환 Lerp 포함 결과값이므로 별도 처리 없음)
- Room 전환 전환(Lerp) 중에도 매 프레임 카메라 위치를 읽으므로 배경이 자연스럽게 따라붙는다. 별도 전환 코드 없음.
- 부활(ForceCameraPosition/OnPlayerRespawn) 시에도 마찬가지로 다음 LateUpdate에서 맞춰진다.
- 스프라이트를 이동하지 않고 Transform 위치만 바꾼다. (스프라이트 교체 없음, 애니메이션 아님)
- 좌우 반전(flipX)·스케일 변경 금지. (배경이 뒤집히거나 크기가 튄다)
- 카메라를 찾지 못하면(비활성 등) 자기 위치를 유지하고 조용히 아무것도 하지 않는다. (에러 폭탄 금지)

==================================================
[4. 배경 폭과 반복]
==================================================

배경 스프라이트가 방보다 좁으면 패럴랙스 이동 중 빈 곳이 보인다.

최소 폭 규칙:

  배경 유닛 폭 ≥ (방 폭 - 카메라 가동 폭) + 카메라 가동 폭 × factor + 여유(0.5 유닛)

- 카메라 가동 폭 = 방 폭 - 카메라 폭(orthographicSize × aspect × 2). (RoomCamera.ClampToRoomBounds 기준)
- subway_BG는 4.96유닛이다. 방이 이보다 넓으면 **수평 타일 반복**이 필요하다.
  방법: Sprite Renderer를 2~3개 나란히 배치해 간격 없이 이어 붙인다. (에셋 가장자리가 맞물리지 않으면 겹침 여유를 둔다)
  반복 오브젝트는 모두 같은 ParallaxLayer factor를 쓰되, 이동 시 타일 전체를 한 덩어리로 움직이고
  카메라가 절반을 넘으면 뒤 타일을 앞으로 재배치하는 **무한 반복**은 v1에서 하지 않는다. (필요 시 [7])
- 수직은 방 높이 기준으로 배경을 위로 채운다. 빈 하늘은 BG_Far 레이어 단색 또는 nuvens로 메운다.

==================================================
[5. 임포트와 배치 규칙]
==================================================

- 배경 PNG는 플레이어와 동일 규격으로 임포트한다. (PPU 100, Point, Sprite Mode Multiple)
- 셀 슬라이싱이 필요 없는 단일 이미지라면 Sprite Mode를 Single로 바꿔도 된다. (배경은 애니메이션이 아니므로)
- 배경 오브젝트는 반드시 Room 자식이다. Room 밖(씬 최상위)에 두지 않는다.
- 좌표 하드코딩 금지. 배경 위치는 Room 중심 기준 배치하고, 실제 수치는 씬에서 조작한다.
- 타일맵(ground)과 배경을 혼동하지 않는다. 타일맵은 충돌 있는 지형, 배경은 판정 없는 연출이다.

==================================================
[6. 구현 목표]
==================================================

1. ParallaxLayer 스크립트 (factor X/Y, 방 중심 기준 공식, LateUpdate)
2. Sorting Layer 생성 (BG_Far, BG_Main, FG)와 배경 오브젝트 배치 규칙 정리
3. Scene 구성: 최소 1개 Room에 subway_BG + nuvens 3장 배치해 검증
4. 방 폭이 배경보다 넓을 때의 타일 이어붙이기 처리
5. Room 전환 Lerp 중 배경이 어긋나지 않는지 확인
6. wall_subway 전경 사용 여부 확정 (옵션)
7. 카메라 LookAhead(조준 방향으로 카메라 밀림)가 배경에 과도하게 전달되지 않도록 점검
   (factor가 낮으면 자연히 억제된다. 문제 생기면 LookAhead 제외 옵션 추가)

==================================================
[7. 열린 결정 사항 (기본값으로 진행, 필요 시 변경)]
==================================================

- 구름 무한 반복: v1에서 미구현. 방 폭이 구름 폭(4.96유닛)을 크게 넘으면 추가. (기본: 타일 이어붙이기만)
- 구름 애니메이션(천천히 흐르는 연출): v1에서 미구현. (기본: 위치 패럴랙스만)
- 배경 전환 연출(방 진입 시 페이드): v1 미구현. Room 전환 시 카메라 Lerp가 끝나는 것만 확인. (기본)
- wall_subway: 전경으로 사용 (기본값은 [2] 표 기준, 실배치 후 확정)
- 배경 고정 색(카메라 Clear Color): subway 배경이 화면을 채우면 불필요. 빈 곳이 보이면 검정 대신 배경색 설정. (기본: Clear Color 유지)
