# Room & Camera System Plan (v5 - Run & Gun)

Unity 6 2D 횡스크롤 총게임의 Room 구조와 카메라 시스템을 구현해줘.

먼저 현재 프로젝트의 카메라 구성(Cinemachine 사용 여부 등), 씬 구조, Room/Stage 관련 오브젝트나 스크립트를 확인한 뒤 구현한다. 기존 구조와 충돌하지 않도록 필요한 부분만 수정한다.

Unity 6에서 Cinemachine을 쓴다면 기본 패키지는 Cinemachine 3.x다. 2.x와 컴포넌트 이름과 네임스페이스가 다르므로(예: CinemachineCamera, CinemachinePositionComposer, CinemachineConfiner2D, Unity.Cinemachine) 설치된 버전을 확인하고 그 버전의 API에 맞춘다. 아래에 적은 컴포넌트 이름은 3.x 기준 후보이며, 속성 이름은 설치된 버전에서 확인한다.

v5에서 바뀐 점:
- 카메라 기준을 "산나비"로 변경: Room 안에 가두는 카메라에서 느슨한 자유 추적 카메라로
- Room 경계를 "가두는 벽"에서 "느슨한 범위(기본) / 완전 제한(옵션)"으로 변경
- 카메라 모드 추가 (Follow 기본, Dialogue 컷 줌, RoomFit 옵션)
- 조준 방향(AimDir) 기반 선행 시야, 대시/낙하 보정 추가
- 연출 연결점 구체화 (흔들림, 히트 스톱, 후처리, 처치 섬광)
- 화면 크기는 미정으로 명시

==================================================
[0. 기준과 확인 정도]
==================================================

카메라 기준은 "산나비"다. 다만 이 문서의 근거는 편집된 쇼츠 영상(훈련장, 가로가 잘려 있음) 하나를 분석한 것이라 확정된 부분과 아닌 부분을 구분한다. 확정이 아닌 항목은 옵션 또는 미정으로 두고, 본편 영상(편집 없는 16:9)으로 다시 확인한다.

영상에서 확인된 것 (기본 동작으로 채택):
- 플레이어를 따라가는 자유 스크롤 카메라. 약간 늦게 따라온다.
- Room 벽 바깥의 빈 공간이 화면에 들어온다. (Room에 꽉 가두지 않는다.)
- 대화 장면은 천천히 줌인하다가 한 프레임 만에 클로즈업(약 3.5배)으로 컷 전환되고, 말풍선이 뜬다.
- 처치 순간 흰 섬광과 짧은 정지감, 화면 일그러짐 같은 연출이 있다.

확정하지 못한 것 (옵션 또는 미정):
- 조준/이동 방향으로 카메라가 앞서 가는 정도
- 전투방에서 방 전체를 보여주며 고정하는지 (RoomFit 옵션으로만 둔다)
- 스윙/이동 중 줌 변화
- 실제 화면 크기와 비율 ([9] 참고)
- 처치 때의 정지감이 게임 기능인지 영상 편집인지

==================================================
[1. Room 정의]
==================================================

Room은 카메라 범위와 적/오브젝트 상태를 묶는 단위다.

- Room 식별자(ID 또는 이름)
- 카메라 범위 영역 (Soft Bounds)
- Room에 속한 적, 오브젝트 목록 또는 스포너
- Room에 속한 체크포인트
- Room별 카메라 설정: 경계 모드(Soft / Hard / Off), 카메라 모드(Follow / RoomFit), 프로필 지정(선택)

Room 영역은 오브젝트(Collider나 Bounds)로 정의하고 코드에 좌표를 하드코딩하지 않는다.

==================================================
[2. 카메라 경계 vs 플레이어 지면]
==================================================

카메라용 Room Boundary와 플레이어 이동용 Ground는 서로 다른 역할이다.

- Room Boundary는 카메라가 보여줄 수 있는 범위만 다룬다.
- 플레이어 이동은 Ground Collider가 담당하고 Room Boundary가 플레이어 이동을 막지 않는다.
- 두 가지를 같은 오브젝트나 레이어로 섞지 않는다.

경계 모드 (Room별 선택, 기본값 Soft):

- Soft: Room 바깥의 빈 공간이 일부 보여도 된다. 넉넉한 범위로 카메라가 너무 멀리 벗어나지 않게만 한다. (CinemachineConfiner2D의 넉넉한 범위 또는 직접 구현)
- Hard: 카메라가 Room 안에서만 움직인다. 좁은 방이나 연출용 방에서 선택한다.
- Off: 경계 없음.

==================================================
[3. 카메라 동작 (Follow 기본 모드)]
==================================================

기본 모드는 느슨한 자유 추적이다. (CinemachineCamera + CinemachinePositionComposer 후보)

- 부드러운 추적: 가로/세로 감쇠(Damping)를 따로 조절한다. 카메라는 약간 늦게 따라온다.
  시작값(플레이하며 조정): 가로 0.5~0.8, 세로 0.8~1.0
- 여유 구간(Dead Zone): 플레이어가 이 안에서 움직이는 동안은 카메라가 움직이지 않는다. 시작값은 화면 폭의 10% 안팎.
- 화면 이탈 제한(Hard Limits): 카메라가 늦게 따라와도 플레이어가 화면 밖으로 나가지 않도록 한계를 둔다. 빠른 이동(대시 등)에서 플레이어를 놓치지 않게 하기 위해 반드시 둔다.
- 조준 선행(Look Ahead): 입력 시스템이 주는 AimDir(0 정면 / 1 위45 / 2 위90 / 3 아래45 / 4 아래90) 값으로 카메라 오프셋을 정한다. 방향별 오프셋 표를 Inspector에서 조절하고, 오프셋이 바뀔 때는 부드럽게 보간한다. 켜고 끌 수 있다. (기본값: 켬. 정도는 미정)
  - 정면은 바라보는 방향 쪽으로, 위/아래는 세로 방향으로 더 보이게 한다.
  - AimDir 계산은 player-state-input-system.md가 담당하고, 카메라는 값만 받는다.
- 이동 선행: 이동 속도 기반 선행(Lookahead)은 옵션. 조준 선행과 합산할 때의 최대 오프셋을 제한한다.
- 대시 보정(대시 포함 시): 대시 중에는 여유 구간을 넓히거나 감쇠를 키워 카메라가 덜 흔들리게 하는 옵션.
- 낙하 보정: 낙하 속도가 임계값을 넘으면 아래쪽을 더 보여주는 옵션.
- 카메라 설정은 프로필(ScriptableObject 등)로 묶어 Room이나 상황별로 바꿀 수 있게 한다.
- 값은 Inspector에서 조절할 수 있게 한다.
- 총게임 특성상 화면 밖에서 쏘는 적이 없도록 카메라 가시 범위와 적 감지 범위의 관계를 확인한다. ([9] 참고)

==================================================
[4. Room 전환]
==================================================

플레이어가 Room 경계를 넘어가거나 전환 트리거에 닿으면 현재 Room을 바꾼다.

- 현재 Room 정보를 한 곳에서 관리한다.
- 전환 시 카메라 경계 설정(Soft/Hard/Off, 범위)을 새 Room 것으로 교체한다. (부드러운 전환 또는 즉시 전환 옵션)
- Soft 경계끼리 전환할 때는 카메라가 갑자기 튀지 않게 감쇠를 유지한다.
- 전환 중 입력/적 AI/투사체 처리 규칙을 정한다. (기본값: 전환 중 플레이어 입력 유지, 필요하면 잠금 옵션)
- Room 진입/이탈 이벤트를 발생시켜 적 활성화/비활성화, 체크포인트가 구독할 수 있게 한다.

==================================================
[5. Room과 적/오브젝트]
==================================================

- 플레이어가 없는 Room의 적은 비활성화하거나 AI를 멈춰 성능을 아낄 수 있게 한다.
- Room 진입 시 적을 활성화하는 규칙을 정한다. (기본값: 진입 시 활성화, 퇴장 시 상태 유지)
- 카메라가 Room 밖을 보여주는 Soft 경계에서는 화면에 보이는 다른 Room의 적이 비활성 상태로 멈춰 있어 보일 수 있다. 화면에 보이는 적의 활성화 기준(Room 기준 / 화면 거리 기준)을 정한다.
- 적 리셋 단위는 Room이다. (checkpoint-respawn-system.md 참고)
- 투사체가 Room 밖으로 나가면 소멸하게 할 수 있다. Soft 경계에서는 Room 밖이 보일 수 있으므로 소멸 기준(Room 밖 / 카메라 밖 일정 거리)을 정한다.

==================================================
[6. 부활과 Room]
==================================================

- 부활 시 체크포인트가 속한 Room을 현재 Room으로 설정한다.
- 부활 후 카메라가 이전 Room의 경계를 계속 사용하는 문제가 없도록 한다.
- 부활 시 카메라 위치를 부활 지점으로 즉시 이동시켜(컷 전환) 이전 위치에서 날아오는 연출이 생기지 않게 한다.
- 부활 시 카메라 모드는 Follow로, 진행 중이던 흔들림/히트 스톱/후처리 연출은 초기화한다.

==================================================
[7. 카메라 모드]
==================================================

모드 전환은 한 곳(예: CameraController)에서만 한다. Cinemachine의 우선순위(Priority)와 CinemachineBrain 블렌드 설정으로 구현한다.

1) Follow (기본): [3]의 자유 추적.

2) Dialogue (대화 컷 줌):
- 대화용 CinemachineCamera를 따로 두고, 켜질 때 우선순위를 올린다.
- 대상은 플레이어와 대화 상대의 중간점이다. (Target Group 또는 지정 Transform)
- 전환은 Cut 블렌드(즉시)가 기본이다. 영상 기준 한 프레임 만에 클로즈업된다.
- 클로즈업 배율은 Inspector 값이다. (영상 기준 약 3.5배. 확정 아님)
- 진입 직전의 천천히 줌인(영상 기준 약 0.6초, 약 25%)은 옵션으로 둔다.
- 대화 중에는 player-state-input-system.md [7]의 입력 차단을 사용한다.
- 대화 중 게임 시간을 멈출지는 옵션이다. (영상에서는 타이머가 멈춰 있었다.)
- 대화가 끝나면 Follow로 돌아온다. (Cut 또는 부드러운 복귀 옵션)

3) RoomFit (옵션, 미확정): Room 전체가 한 화면에 들어오게 카메라를 맞추는 모드. 전투방 등 특정 Room에서만 선택한다. 영상으로 확정하지 못했기 때문에 필수가 아니다.

4) Respawn Cut: [6]의 부활 컷 전환.

==================================================
[8. 연출 연결점]
==================================================

카메라 시스템은 게임 로직을 직접 호출하지 않고 이벤트를 구독해서 반응한다. 아래는 구현하지 않아도 연결할 수 있는 지점만 만든다.

- 카메라 흔들림: CinemachineImpulseSource 후보. 발사(weapon-projectile-system의 OnFired), 피격과 사망(health-damage-system의 이벤트)에 연결한다. 세기는 이벤트별 Inspector 값.
- 히트 스톱: 처치/피격 때 짧게 정지시키는 연결점. Time.timeScale 변경과 unscaled 시간 기반 복구를 쓰되, 일시정지·대화 정지와 충돌하지 않도록 한 곳에서 관리한다. (정지감이 게임 기능인지는 미확정이므로 옵션)
- 후처리 펄스: 화면 일그러짐/색 번짐을 Volume 가중치 변화로 짧게 준다.
- 처치 섬광: 적 처치 시 흰 섬광과 베는 선 같은 연출을 붙일 수 있는 연결점.
- 모든 연출은 플레이어 사망/부활 시 초기화하고, 겹쳐 쌓이지 않게 한다.

==================================================
[9. 화면 크기와 가시 범위 (미정)]
==================================================

산나비의 실제 화면 크기와 비율은 확정하지 못했다. 참고 영상이 가로로 잘려 있어 캐릭터가 화면에서 차지하는 비율을 신뢰할 수 없기 때문이다. 아래는 Phase 0의 결정 항목이다.

- 기준 해상도와 Orthographic Size (또는 Pixel Perfect Camera 사용 여부)
- 가시 범위가 정해지면 점검할 것:
  - 적 감지/사격 거리가 화면 반폭보다 짧은가 (화면 밖에서 쏘는 적 방지)
  - 투사체 소멸 기준 ([5])
  - 위/아래 조준 선행 오프셋이 화면 안에 들어오는가
  - 스프라이트 규격(sprite-asset-spec의 PPU 등)과 일치하는가

[10. 구현 목표]
==================================================

1. Room 정의와 식별 (경계 모드 포함)
2. 카메라 경계와 Ground 분리
3. 느슨한 자유 추적 카메라 (감쇠, 여유 구간, 화면 이탈 제한)
4. 조준 선행 (AimDir 기반), 대시/낙하 보정
5. 카메라 모드 (Follow, Dialogue 컷 줌, RoomFit 옵션)
6. Room 전환과 Room 이벤트 (적 활성화 등)
7. 부활 시 Room/카메라/연출 갱신
8. 연출 연결점 (흔들림, 히트 스톱, 후처리, 처치 섬광)
9. 하드코딩 최소화
