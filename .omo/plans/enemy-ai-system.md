# Enemy AI System Plan (v2 - 2D Run & Gun)

Unity 2D 횡스크롤 총게임의 기본 적 AI를 구현해줘.

현재 Enemy 구조, Collider2D, 공격(사격) 애니메이션, Health, Projectile/Weapon 시스템을 먼저 확인한다.
이 문서의 적은 원거리 사격형이 기본이다. 근접형, 터렛, 비행형은 같은 구조에서 데이터와 상태 추가로 확장한다.

==================================================
[1. 상태 기반 AI]
==================================================

Enemy AI는 상태 기반으로 구성한다.

기본 상태:

- Idle (또는 Patrol)
- Detect
- Chase / Reposition (거리 조절)
- Aim
- Shoot
- Cooldown (재장전 포함)
- Hurt
- Dead

선택 상태:

- Stunned (특수 무기나 누적 경직용으로만 사용. 기본은 제외)
- Alert / Search (플레이어를 놓쳤을 때 잠시 수색)

삭제된 개념: 패링 대응용 Stunned, 근접 공격 전조.

이후 상태를 쉽게 추가할 수 있게 한다.

==================================================
[2. 플레이어 감지]
==================================================

감지 조건을 Inspector에서 조절할 수 있게 한다.

- 감지 거리
- 시야각 (전방만 볼지 전방위인지)
- 시야 판정: 플레이어까지 Raycast/Linecast로 벽이나 지형에 가려졌는지 확인 (LayerMask 사용)
- 감지 해제 조건: 일정 시간 동안 시야를 잃으면 Idle로 복귀
- 피격 시 방향 무관하게 감지하는 옵션

무조건 플레이어 Transform을 따라가는 방식이 아니라 감지 조건을 통해 상태를 변경한다.

==================================================
[3. 이동과 거리 유지]
==================================================

감지 후 사격 가능한 거리로 이동한다.

- 선호 거리 범위 (Min Range / Max Range)를 Inspector에서 조절한다.
- 너무 가까우면 후퇴(Retreat)하거나 제자리에서 사격할지 옵션으로 둔다.
- 너무 멀면 접근한다.
- 플레이어와 겹치지 않도록 한다.
- 낭떠러지와 벽을 감지해서 떨어지거나 벽에 끼지 않도록 한다. (Ground/Wall Check)
- 적의 이동용 Ground 판정과 카메라용 Room Boundary는 구분한다.

==================================================
[4. 사격]
==================================================

Enemy 사격은 Weapon/Projectile 시스템과 Hitbox/Hurtbox 시스템을 사용한다.
적이 총알 생성 로직을 직접 들고 있지 않고, 무기/투사체 데이터를 사용한다.

- 조준 시간(Aim Time): 감지 후 바로 쏘지 않고 조준 후 발사
- 발사 전 예고(Telegraph): 조준선, 사운드, 모션 등 플레이어가 반응할 수 있는 신호
- 연사 방식: 단발 / 버스트 / 연사 (발수, 간격)
- 쿨다운과 재장전
- 정확도: 탄 퍼짐(Spread)과 조준 오차
- 조준 대상: 플레이어의 현재 위치 기준. 예측 사격(Lead)은 옵션
- 발사 위치는 Muzzle Transform 기준
- 공격 애니메이션과 실제 발사 시점을 분리한다.
- 팀/레이어 필터: 적 총알은 플레이어만 맞히고 다른 적이나 무관한 Collider를 맞히지 않는다. (아군 사격 옵션은 별도)

==================================================
[5. 피격]
==================================================

Enemy가 공격을 받으면:

- Damage 처리 (Health/Damage Receiver)
- 피격 피드백 (Hit Flash, 사운드)
- 약한 Knockback (옵션)
- 경직(Hurt 상태)은 누적 피해량(Poise)이 임계값을 넘을 때만 발동

총알 한 발마다 경직되면 연사에 적이 계속 굳어 버린다. 일반 피격은 Hurt 상태로 가지 않고 피드백만 보여주고, 경직은 임계값 또는 특정 공격 조건에서만 처리한다.

- 피격 중 AI가 즉시 Chase나 Shoot로 돌아가지 않도록 상태 우선순위를 관리한다.
- 피격 후 상태를 다시 판단한다. (플레이어 위치, 시야 재확인)
- 사격 중 경직되면 진행 중이던 조준/버스트를 안전하게 중단하고 Hitbox/투사체 생성이 남지 않게 한다.

==================================================
[6. 사망]
==================================================

체력이 0이 되면 Dead 상태로 전환한다.

- Dead 상태에서는 이동/사격/감지를 중단한다.
- 사망 판정과 사망 애니메이션, 실제 제거 시점을 분리한다.
- 제거는 Destroy가 아니라 비활성화(또는 풀 반환)를 기본으로 한다. Checkpoint System의 적 리셋 정책에서 다시 활성화할 수 있어야 하기 때문이다.
- 사망 시 이미 발사된 총알의 처리(유지/제거)를 명확히 한다.

==================================================
[7. 다수 적과 성능]
==================================================

한 번에 하나의 적을 상대하는 구조라도 이후 여러 적이 존재할 수 있도록 AI를 특정 Enemy 하나에 하드코딩하지 않는다.

- 같은 AI 코드에 데이터(체력, 사거리, 연사 패턴, 무기)만 바꿔 여러 적을 만들 수 있게 한다. (ScriptableObject 등)
- 동시에 사격하는 적 수를 제한할 수 있는 옵션(Attack Token)을 고려한다.
- 총알은 오브젝트 풀링을 사용한다.
- 적 간 겹침과 밀림을 최소화한다.

==================================================
[8. 확장 적 유형]
==================================================

지금은 구현하지 않아도 아래 유형을 추가할 수 있는 구조로 만든다.

- 터렛형: 이동 없음, 조준과 사격만
- 근접 돌진형: Chase → Attack(근접 Hitbox)
- 비행형: 중력 무시 이동, 2D 평면 거리 유지

==================================================
[9. 구현 목표]
==================================================

1. 상태 기반 AI (사격 흐름: Aim → Shoot → Cooldown)
2. 플레이어 감지 (거리, 시야, Raycast)
3. 거리 유지와 이동 (낭떠러지/벽 감지)
4. 사격 (조준, 예고, 연사, 정확도)
5. 피격 (누적 경직, 히트 피드백)
6. 사망 (비활성화 기반, 리셋 가능)
7. Inspector 조절
8. 다수 적 확장 (데이터 분리, 풀링)
9. 이후 유형 추가 가능
