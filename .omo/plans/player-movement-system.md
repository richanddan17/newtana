# Player Movement System Plan (v2 - Run & Gun)

Unity 2D 횡스크롤 총게임의 플레이어 이동 시스템을 구현해줘.

먼저 현재 프로젝트의 Player 오브젝트, Rigidbody2D, Collider2D, 기존 PlayerController 및 이동 관련 스크립트를 확인한 뒤 구현한다. 기존 구조와 충돌하지 않도록 필요한 부분만 수정한다. Unity 버전에 따라 Rigidbody2D 속도 API(velocity / linearVelocity)가 다르므로 프로젝트가 쓰는 쪽에 맞춘다.

상태 우선순위와 상태별 이동 허용 규칙은 player-state-input-system.md를 따른다.

==================================================
[1. 기본 이동]
==================================================

플레이어는 좌우 방향으로 이동한다.

- 좌우 입력 처리
- 이동 속도, 최대 이동 속도
- 가속/감속
- 방향 전환
- 정지 시 감속

이 값들은 Inspector에서 조절할 수 있도록 한다.

==================================================
[2. 이동하면서 사격]
==================================================

총게임이므로 이동과 사격이 서로 막지 않는 것이 기본이다.

- 사격 중에도 이동 가능 (기본값)
- 사격 중 이동 속도 배율을 Inspector에서 조절할 수 있게 한다. (1.0이면 감속 없음)
- 사격 중 제자리 고정 옵션(조준 고정)을 둘 수 있게 한다.
- 이동 방향과 바라보는 방향이 다를 수 있다. (뒤로 걸으며 사격) 이 경우 이동은 입력 방향, 바라보는 방향은 조준 방향을 따른다.
- 사격 반동(Recoil)으로 인한 뒤로 밀림은 옵션으로 두고, 기본은 꺼 둔다.

==================================================
[3. 지상과 공중 이동]
==================================================

지상 이동과 공중 이동을 구분한다.

- 지상에서는 설정된 이동 속도까지 자연스럽게 가속한다.
- 공중에서도 일정 수준의 좌우 제어가 가능해야 한다.
- 공중 제어력은 지상과 별도로 조절할 수 있어야 한다.
- 공중에서 방향을 바꿀 때 기존 속도와 새 입력이 비정상적으로 충돌하지 않도록 한다.
- 공중에서도 사격이 가능하다. 공중 사격 중 이동 규칙은 지상과 별도로 설정할 수 있다.

==================================================
[4. 점프]
==================================================

점프는 Rigidbody2D의 물리 구조와 충돌하지 않도록 구현한다.

- Ground 판정
- 점프 입력, 점프 힘
- 최대 점프 높이
- 점프 컷(키를 일찍 떼면 낮은 점프): 활성/비활성 옵션
- 낙하 처리, 최대 낙하 속도

Coyote Time과 Jump Buffer를 Inspector에서 활성화/비활성화할 수 있도록 한다.
Jump Buffer 입력은 입력 시스템의 버퍼를 사용한다.

==================================================
[5. 바닥 판정]
==================================================

단순히 플레이어의 Y좌표를 기준으로 바닥을 판단하지 않는다.

Collider2D 또는 Ground Check를 이용해 실제 지면 접촉을 판단한다.

- 내부 플랫폼도 실제 플레이어 이동용 Ground라면 정상적으로 바닥으로 인식한다.
- 일방향 플랫폼, 경사면, 이동 플랫폼이 프로젝트에 있는지 확인하고, 있으면 처리한다. 없으면 확장 가능하게만 둔다.
- 벽에 붙어 떨어지지 않는 문제를 막기 위해 마찰이 없는 Physics Material 사용을 확인한다.
- 카메라용 Room Boundary와 플레이어 이동용 Ground는 서로 다른 역할이므로 혼동하지 않는다.

==================================================
[6. 상태별 이동 제한]
==================================================

피격, 대시, 사망 등의 상태에서 이동 가능 여부는 State System의 상태별 허용 표에서 가져온다.

각 상태마다 이동을 하드코딩으로 막지 않는다.

==================================================
[7. 대시 및 넉백 (외부 속도)]
==================================================

대시가 포함되어 있다면 일반 이동 속도와 분리한다.
대시와 마찬가지로 피격 넉백도 "외부 속도"로 취급한다.

- 대시나 넉백 중에는 일반 이동 입력이 해당 속도를 덮어쓰지 않는다.
- 종료 후 정상적인 이동 상태로 자연스럽게 복귀한다.
- 넉백 값은 Health/Damage 시스템에서 전달받는다.

==================================================
[8. 물리 및 애니메이션 연결]
==================================================

Rigidbody2D의 실제 속도와 애니메이션 상태가 일치하도록 한다.

- 수평 속도 > 일정 값 → Run
- 수직 속도 > 0 → Jump/Rising
- 수직 속도 < 0 → Fall
- 지상 + 이동 없음 → Idle

애니메이션 전환 로직과 실제 이동 로직을 서로 강하게 결합하지 않는다.
애니메이션은 이동 결과값을 읽기만 한다.

==================================================
[9. 구현 목표]
==================================================

1. 자연스러운 좌우 이동
2. 안정적인 지상 판정
3. 점프와 낙하
4. 공중 제어
5. 이동하면서 사격 (속도 배율, 조준 고정 옵션)
6. 대시/넉백 등 외부 속도와의 연동
7. 상태 시스템과 연동 (이동 허용 규칙)
8. Inspector에서 주요 수치 조절 가능
9. 기존 프로젝트 구조와 충돌하지 않는 구현
10. 월드 좌표를 하드코딩하지 않는 구현
